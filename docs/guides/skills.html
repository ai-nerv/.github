Skills

A workflow written down once and picked by name: a Markdown file, put into the turn that asked for it. It is text, not code, and it grants nothing.

A first one

# .magi/skills/review/SKILL.md
---
name: review
description: "Review changes: correctness and tests"
---
Review the requested files for correctness and missing tests.
Explain findings before proposing edits.

Then, at the prompt, /skill review src/lib.rs. /skill completes the names, and :skills refreshes them. The same works where nobody is typing:

magi -p '/skill review src/lib.rs'

Where they are found

firstroot
1.magi/skills/<name>/SKILL.md, under the directory magi was started in
2.agents/skills/<name>/SKILL.md, the same
3~/.config/magi/skills/<name>/SKILL.md, yours, everywhere

Only those three, and only one level deep. There is no walk up to a parent, no search of a repository's root, and no reading of another tool's directories — a nested directory does not quietly pick up a skill from above it. magi.workflow_workspace, in your own configuration, names another root.

What it is, and is not

  • Text. The body is added to that turn's context, and kept with the run in balthasar, with where it came from — so a resumed session knows what it was told.
  • Not a template. Arguments are appended as data, labelled as data. Nothing is substituted, nothing is expanded, and a $(…) in an argument is the characters $(…).
  • Not a grant. A skill that says “run the tests” is a request like any other. Every action it leads to passes the same ledger.
  • Not code. It is not a Lua plugin and cannot declare a tool. That is what writing a tool is for.
A skill that cannot be found is refused, visibly. A bare /skill, a bad name or a missing file is an error rather than an ordinary prompt sent to the model — and magi -p exits non-zero rather than carrying on as though it had been asked something else.
