MCP, both ways

casper speaks the Model Context Protocol in both directions: outside servers become tools a session can call, and casper's own tools are a server something else can call.

An outside server, as tools

One JSON file per server, named after it, in casper's data directory — and nowhere else. No other program's configuration is read, and no project's.

# ~/.local/share/casper/mcp/filesystem.json
{
  "command": "/absolute/path/to/an/mcp-server",
  "args": ["--root", "/your/project"],
  "needs": "run",
  "timeout_secs": 60
}

A server over HTTP gives a url and its headers instead. Its tools appear in the session as mcp__<server>__<tool>, and the tools manual describes each server and what it offers. A server that will not start costs its own tools and nothing else.
where it runsa server over stdio starts inside the jail, with only its own environment. One over HTTP needs the network granted, like any other reach.
what it may doits needs is the permission verb every call is asked under — the ledger does not know or care that the tool came from MCP
who signs incasper mcp-auth runs a server's OAuth, with your browser and your consent; mcp-status and mcp-logout do the rest
between callsa server's session is kept while magi holds casper's serve open — which is what that door exists for

Your own configuration can also name servers through casper's settings, and those win over a file of the same name:

magi.casper = {
  mcp_servers = {
    remote = { url = "https://example.org/mcp", needs = "reach",
               headers = { Authorization = "Bearer …" } },
  },
}

casper's tools, as a server

casper mcp --root /path/to/project --tools=read,web

Any MCP client can then call casper's tools over stdio. Started this way, casper runs every command in its conservative jail unless told otherwise — the one place it defaults to jailed rather than to whatever its spawner chose, because here the spawner is somebody else's program. A tool that is off or hidden is not offered; a call that is cancelled or runs out of time stops the process it started.

magi has no MCP client of its own. Running a tool is casper's, whoever wrote it — so an MCP server's tools pass the same jail, the same ledger, the same output cap and the same secret masking as casper's own, through the one door every tool already uses.
