casper

The tools a coding agent runs, the jail every command runs in, and the screen they draw on. It knows nothing about models, turns or transcripts.

What it offers

Nineteen tools. Ten are in front of the model on every request; the other nine are deferred — listed in the tools manual and declared only when the model asks for them, so they cost nothing until then.

toolsfor
read write edita file — text, or an image resized and sent as an image. edit replaces an exact piece and answers with the diff.
ls tree codethe shape of the tree, and a source file's skeleton — types, signatures, line ranges — for a fraction of reading it
sesewhere something lives, by meaning rather than by string: a ranked list of passages and nothing else
shell executea command; or a Python script in which the read-only tools are functions, for a chain of looks in one call
toolsthe manual: the deferred tools, and every outside MCP server's
weba search, or one page fetched and read — no scripts run. Deferred.
screenan interactive program — a pager, an editor, htop, git add -p — in a block of its own. Deferred.
hexe oslo sessionasking the multiplexer, the shell, or the harness about themselves. Deferred.
dino birdy doom gamesgames, because a surface that can draw a game can draw anything. Deferred.

Every one is declared in Lua, in ~/.config/casper/tools.lua, read fresh on every call — editing it changes the tools on the next one, no rebuild. code parses through grammars casper does not ship: casper grammar fetch builds the pinned set into your data directory.

Adding your own

A file in a directory. Nothing to register, no entry point to edit:

~/.config/casper/plugin/yours.lua              alphabetical, each on its own
~/.local/share/casper/site/pack/*/start/*/plugin/*.lua   installed packages
~/.config/casper/after/plugin/yours.lua        the last word

The registry replaces by name, so the order is the precedence: a file declaring cat means it, and after/plugin/ is how you override something you did not write. make install overwrites tools.lua and never touches these. See writing a tool.

A package you fetched does not run until you say so. Files you put in your own plugin/ directory run on sight. Anything under site/pack/ is held back until casper acknowledge records its digest, and held back again the moment it changes.

magi.casper = { tools = { dino = { off = true } }, output_bytes = 65536 }

The jail

Every command casper runs — a shell call, a screen, an MCP server it starts — runs in a kernel jail magi chose when it started casper, never one the call names. bubblewrap where it is installed; Landlock and seccomp where it is not; and where neither can be fully enforced, the command is refused rather than run without one.

inside
readssystem and toolchain directories, and the workspace
writesthe workspace, the grants magi added, and a private temporary directory
the networkopen when magi says so — it is essential to most work — and nothing local through it: no host Unix socket, no abstract one where the kernel can scope it
your keyscredential stores, the home directory's dotfiles, and anything they link to are unreadable, even when a grant would cover them — that grant is refused
a project's own config.magi.lua, .balthasar.lua, .git/config and .git/hooks stay read-only, so a command cannot change what the next unjailed program will run
the kernelptrace, bpf, io_uring, mounts, new namespaces and their kin fail with EPERM

The environment is an allowlist, not what magi inherited: a provider key in your shell is not in the command's. magi turns the jail on for every session unless your own configuration says magi.isolation = false, and a project file cannot.

A spawn, or a socket

casper's job is running programs, and a socket that runs commands is a remote shell wearing a friendly name — unless it can run nothing its spawner could not. By default magi spawns casper once per call. casper serve is the other door: one process for the session, whose jail is the one it was started in, answering only calls that carry the key it read on stdin. It exists because an MCP server's session has to survive between calls.

casper fills the tools role, and is the default rather than the only choice. magi.tools hands the role to any program that answers tools and run — see swapping a program. The settings table follows the program’s own name, so magi.casper is casper’s because casper is the one filling the role.

At a terminal

casper tools                 every tool it offers, as declarations a harness can register
casper run <tool>            run one; the call arrives as JSON on stdin
casper serve --at <path>     one process for a session, on a keyed socket
casper surface <tool>        hold rows on the harness's screen and draw into them
casper mcp                   its own tools, as an MCP server on stdio
casper mcp-auth · mcp-status · mcp-logout   an outside server's OAuth
casper code <path>           a source file's outline
casper grammar fetch         build the grammars code parses with
casper image <path>          read and resize an image
casper verbs                 what it answers, on each of its doors
casper needs                 what a coordinator may tell it
casper configure             take that configuration, as Lua on stdin
casper acknowledge           clear the installed packages, so their declarations may run

casper tools --cbor          the same reply, as bytes
