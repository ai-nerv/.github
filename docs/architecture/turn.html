A turn, end to end

One line typed, one answer back. Each column is a separate process, and each hop can fail.

The model never reaches anything

It emits a request naming a tool. magi decides whether it may run — or the mode it is in decides who is asked — and casper runs it, inside the jail magi chose. Nothing the model says becomes an action without passing the ledger — see what may run.

What the model is actually sent

Not the transcript verbatim, and not magi's choice. Before every request magi asks balthasar for a layout, and renders what comes back. In the order the prompt cache wants it:

  • the system message — what magi is, the date, this session's directory and platform, and the project's AGENTS.md.
  • every tool declaration the registry holds that is not deferred, as a schema the model can call. The rarely needed ones are behind casper's tools manual.
  • rules, on the user's channel: standing instructions a person actually gave, each checked against the line they gave it in.
  • observations and the catalog, as helper context: what was noticed, and one line per thing the project holds as true — with the last line saying whether that is everything.
  • the conversation — word for word, a tool result cut to a stub, or a stored summary where a span of it was.
  • memory, just before the latest prompt: what is current, stated, and what is merely on record, hedged under a heading that says so.
balthasar decides, and never calls a model. When a summary is due, notes could be drawn from a turn, or two claims disagree, the layout hands magi a job — an instruction, an input, a schema — and magi runs it on a helper model and hands the answer back. See memory.
